# Validation and limits

The initial public source release was prepared on November 4, 2026. Publication evidence and hosting choices are maintained in the [release record](docs/releases/0.1.0.md). No public registry or marketplace entry is provided.

## Executed

- Eleven Python/Git and package tests cover read-only history inspection, removed fake secrets, inherited Git redirection, annotated tags, replacement objects, shallow clones, binary coverage, limits, empty/invalid repositories, local links and standalone installed-folder execution.
- A standalone temporary copy passed internal-resource completeness, format validation and helper invocation from outside the checkout; temporary files were removed.
- The skill-creator frontmatter validator passed. Local links, whitespace, source privacy patterns and file responsibilities were reviewed.
- The workflow was applied to an existing public-tool release: compatible GitHub Actions updates were reviewed and merged, an incompatible Python build minimum was declined, hosting settings were checked and repetitive generated instructions were repaired.

## Acceptance boundaries

This practical application is not an independent model evaluation. The host now lists the installed skill in its available-skills catalog, confirming discovery in this session. Behavior across other agents, every GitHub plan and end-to-end agent behaviour have not been independently accepted. The linked local skill directory is the source of truth; no private account credentials or project configuration belong here.

The history helper is supporting evidence. Its reference documents define exact limits, including filenames, binaries, remote refs and unrecognized secret patterns. Human judgment still decides publication scope, findings and feature costs.

## Review follow-up

The entry point now explicitly requires current official GitHub research for each publication or hosting audit, scoped to relevant options and the actual account. The hosting reference defines a dated, source-backed selection record and separates AI scanning from an application's own AI use. The skill-package reference adds installable-folder completeness and observable behavioural evaluation cases, without claiming those cases were executed. Validation remains package/helper evidence and a practical first application, not an independent model evaluation.
